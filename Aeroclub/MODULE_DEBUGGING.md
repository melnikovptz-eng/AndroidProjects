# Отладка модулей Aeroclub

Ветка: `aeroclub-informer`. Изменения ограничены каталогом `Aeroclub/`.

## Что реализовано в исходниках

- Общий `ModuleDebugLog`: пишет JSONL в приватный файл приложения и отдельную устойчивую очередь неподтверждённых записей.
- Активный локальный журнал: `module-debug.log`; резервная копия: `module-debug.log.1`; активный файл ротируется при размере 1 MiB.
- Автоматическая отправка очереди после 50 строк.
- Внеочередная отправка при исходе, похожем на ошибку/сбой/тайм-аут.
- Повторная отправка очереди при возвращении сетевого соединения, если предыдущая отправка завершилась ошибкой.
- Ручная кнопка «Отправить лог-файл в GitHub» в админ-панели отправляет полный доступный журнал (резервная копия + активный файл).
- Автоматические пакеты содержат только ещё не подтверждённые строки; каждый пакет получает уникальный путь в `uploads/`, чтобы параллельные устройства не перезаписывали один общий файл.
- `DebugOperation` измеряет длительность через монотонные часы и пишет `duration_ms`.
- Уже измеряется время первоначального открытия информера и панели администратора; для полного покрытия остальные значимые операции должны оборачивать начало/завершение через `ModuleDebugLog.startOperation(...)` и `finish(...)`.
- Переходы между разделами админ-панели регистрируются централизованно.
- Отправка выполняется в отдельном однопоточном исполнителе; ошибка загрузки не вызывает повторную запись в тот же логгер.

## Формат события

Поля: `time`, `module`, `action`, `outcome`, `detail`, `thread`; у завершённых измеряемых операций добавляется `duration_ms`.

## Настройка GitHub

Клиент сейчас нацелен на публичный репозиторий `melnikovptz-eng/Aeroclub-Debug`, ветку `main`, и пишет уникальные пакеты в `uploads/<timestamp>-<uuid>.jsonl`.

**Репозиторий ещё требуется создать вручную** как публичный и инициализировать README, чтобы существовала ветка `main`. Для записи нужен fine-grained token с правом `Contents: Read and write`, ограниченный только этим репозиторием.

Токен не хранится в исходниках. При сборке он внедряется в APK через переменную окружения `AEROCLUB_DEBUG_GITHUB_TOKEN`; в Gradle-конфигурации `core/data/build.gradle` пустая переменная приводит к понятной ошибке отправки, а не к аварийному завершению приложения. Для сборки с активной отправкой задайте эту переменную в окружении Gradle/CI. Встроенный в APK токен можно извлечь; публичный журнал должен содержать только диагностические сведения.

## Что пока не подтверждено

- Не выполнены сборка Gradle, установка APK и проверка реальной отправки с устройства.
- Не проверены права токена, доступность репозитория и фактическое появление пакета на GitHub.
- Полнота таймингов всех операций пока не достигнута: добавлен общий API измерения и замер открытия основных экранов, но не все операции каждого модуля уже обёрнуты.
- До CI и device-тестов нельзя считать весь механизм проверенным.

## Обязательные сценарии проверки

1. Записать 50 событий и проверить автоматическое появление пакета.
2. Записать событие с результатом `error` и проверить внеочередную отправку.
3. Отключить сеть, накопить записи, восстановить сеть и проверить повторную отправку.
4. Нажать ручную кнопку и убедиться, что отправлен полный доступный журнал.
5. Проверить HTTP 401/403, отсутствие токена, несуществующий репозиторий и повторный запуск отправки.
6. Проверить, что неотправленные записи остаются в очереди и не удаляются при ошибке.
7. Проверить, что продолжительность операции отображается как `duration_ms` и не зависит от изменения системных часов.
