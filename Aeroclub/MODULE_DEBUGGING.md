# Отладка модулей Aeroclub

Ветка: `aeroclub-informer`  
Область: только `Aeroclub/`

## Отдельный файл

- Имя: `module-debug.log`
- Путь Android: `<private app files directory>/module-debug.log`
- Резервный файл при ротации: `module-debug.log.1`
- Формат: JSON Lines — одна JSON-запись на строку.
- Максимальный размер активного файла: 1 MiB; при превышении текущий файл ротируется в один резервный файл.
- Просмотр: админ-панель → «Уведомления» → «Открыть файл отладки всех модулей».
- Это приватный файл приложения на текущем устройстве, не общая база и не сетевой лог.

## Поля записи

`time`, `module`, `action`, `outcome`, `detail`, `thread`.

Журнал событий `EventLogRepository` зеркалируется в этот файл. Дополнительные диагностические точки фиксируют жизненный цикл информера, локальный транспорт объявлений, наблюдатель файла, планировщик напоминаний и обновление виджета.

## Правила безопасности

- Не писать имена участников, содержимое сообщений, контакты, пароли, токены или секреты.
- В `detail` передавать только короткие технические коды, счётчики и тип исключения.
- Открытие системного меню «Поделиться» не считать доставкой.
- Локальное объявление не считать отправленным на другие устройства.
- Отладочная запись не должна вызывать `EventLogRepository.record` и не должна создавать рекурсивную цепочку логирования.
- Ошибка диагностической записи не должна ломать пользовательскую операцию.

## Что уже покрывается кодом

- События, которые отправляют модули через `EventLogRepository`, дополнительно попадают в отдельный файл.
- Информер: создание/возобновление/пауза/закрытие экрана, обновление объявления.
- Локальные объявления: отклонение некорректного ввода, запись/чтение/ошибка хранилища, тестовая симуляция входящего сообщения.
- Наблюдатель файла: старт/остановка и ошибки чтения.
- Напоминания: синхронизация, планирование и отмена.
- Виджет: получение действия, обновление и отрисовка.

## Оставшиеся проверки

- Пройти на устройстве все основные сценарии: создать/изменить/удалить вылет; добавить/переименовать/удалить участника; изменить ответ; сохранить настройки; подготовить сообщение; записать объявление; включить/отключить уведомления; нажать каждую кнопку виджета.
- Сверить ожидаемое событие с записью в файле после каждого сценария.
- Проверить повреждённый файл, отказ записи и ротацию файла.
- Запустить CI сборку и тесты на точном SHA ветки.
- Пока CI и устройство не проверены, статус — «диагностические точки добавлены, полнота и runtime-поведение не подтверждены».
