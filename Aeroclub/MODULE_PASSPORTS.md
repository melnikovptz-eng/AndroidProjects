# Реестр и паспорта модулей — «Аэроклуб · информер»

Версия: 1.0  
Проект: `Aeroclub/` · ветка `aeroclub-informer`

## 1. Правило паспортизации

Каждый модуль обязан иметь:
- ID и название;
- тип/слой;
- цель и ответственность;
- функции внутри границ модуля;
- входные данные и выходы/события;
- хранилище и модель данных;
- зависимости и запрещённые зависимости;
- обработку ошибок;
- состояние: **реализован**, **частично реализован**, **не реализован**, **заблокирован внешними данными**;
- тест-кейсы и критерии готовности;
- список ограничений и владельца/следующий шаг.

Модуль считается готовым только когда код существует, сценарии проверены, критерии приёмки выполнены и паспорт обновлён. Наличие кнопки или экрана само по себе не означает готовность функции.

## 2. Правила классификации и деления

- **UI/Presentation** — отображение и пользовательские действия; не хранит бизнес-правила и не выполняет прямой сетевой доступ.
- **Domain/Business** — модели, правила выбора активного вылета, статусы участия и валидация.
- **Data/Repository** — единый интерфейс чтения/изменения данных и преобразование форматов.
- **Platform/Integration** — Android Widget, карты, системный chooser, FCM и внешние API.
- **Admin feature** — отдельная административная возможность, использующая общие модели/репозитории, а не копирующая их.
- **Infrastructure** — авторизация, синхронизация, журналирование, диагностика, конфигурация.
- Один модуль отвечает за одну предметную функцию; экран может объединять визуальные компоненты, но не должен поглощать репозиторий, сеть и бизнес-логику.
- Общие данные имеют один источник истины. Не заводить разные ключи/реализации одного и того же поля в виджете, превью и админке.
- Зависимости направляются от UI к доменным интерфейсам/репозиториям; платформенные адаптеры не должны управлять экранами.
- Не создавать параллельные реализации функции. При замене сначала определить старый источник истины и план миграции.
- Название модуля не означает, что он реализован. Статус в реестре обязателен.

## 4. Паспорта модулей

### UI-01 — Карточка информера
- **Назначение:** показать ближайший вылет и четыре основные команды.
- **Вход:** модель активного вылета, статус текущего ответа.
- **Выход:** события ответа, перехода к маршруту и подготовки сообщения.
- **Зависимости:** общий слой данных, Android UI.
- **Не входит:** собственное хранилище вылета, отправка сообщений, сетевые запросы.
- **Ошибки:** пустые поля, отсутствие данных; показывать нейтральный текст.
- **Приёмка:** порядок и стиль соответствуют утверждённому макету; ключевой текст не обрезается; действия имеют понятный результат.
- **Статус:** частично реализован; превью создаётся программно, визуальная проверка на устройстве ещё требуется.

### WID-01 — Виджет
- **Назначение:** показывать карточку на домашнем экране Android.
- **Вход:** данные активного вылета и ответ участника.
- **Выход:** обновлённый RemoteViews, события ответа/маршрута/поделиться.
- **Зависимости:** AppWidgetManager, общий репозиторий.
- **Не входит:** отдельная бизнес-логика вылетов и независимое хранилище.
- **Ошибки:** отсутствующие значения, недоступные приложения; безопасный fallback.
- **Приёмка:** несколько виджетов обновляются корректно; данные переживают перезапуск; изменения из админки видны без ручной переустановки.
- **Статус:** частично реализован; использует SharedPreferences напрямую.

### UI-02 — Экран-превью
- **Назначение:** показывать карточку информера внутри приложения и открывать админ-панель.
- **Вход:** те же данные, что у виджета.
- **Выход:** события ответа и интеграций.
- **Зависимости:** общая модель/репозиторий, Android UI.
- **Не входит:** отдельная копия бизнес-правил.
- **Ошибки:** обрабатывать отсутствие приложения карт.
- **Приёмка:** значения и действия согласованы с виджетом.
- **Статус:** частично реализован; общая логика пока частично дублируется с виджетом.

### ATT-01 — Ответ участника
- **Назначение:** зафиксировать «еду» / «не еду» для конкретного участника и вылета.
- **Вход:** participantId, flightId, значение ответа, время.
- **Выход:** сохранённый ответ и пересчитанная сводка.
- **Зависимости:** Participant/Flight/Attendance models, репозиторий.
- **Ошибки:** повторный ответ обновляет запись, а не создаёт дубль; отсутствие идентификатора должно быть явно обработано.
- **Приёмка:** ответ привязан к конкретному вылету и участнику; сводка вычисляется из записей.
- **Статус:** частично реализован; добавлен AttendanceRepository с ключом локального participantId + flightId; реальная авторизация и синхронизация ещё отсутствуют.

### FLT-01 — Управление вылетами
- **Назначение:** CRUD вылетов и выбор активного.
- **Вход:** название, дата/время, место, статус.
- **Выход:** список вылетов, активный flightId, событие обновления.
- **Зависимости:** модель Flight, репозиторий, календарь, виджет.
- **Ошибки:** невалидная дата/время, пустое название, удаление активного вылета.
- **Приёмка:** несколько вылетов сохраняются независимо; создание не перезаписывает другой вылет; активный вылет однозначен.
- **Статус:** частично реализован; реализованы локальный список, создание, редактирование, удаление, выбор активного вылета и миграция старых полей. Серверной синхронизации и автоматических тестов пока нет.

### PAR-01 — Участники
- **Назначение:** вести список участников и статусы по каждому вылету.
- **Вход:** идентификатор, имя, разрешённые контактные поля, ответ на вылет.
- **Выход:** список, фильтры и точные счётчики.
- **Зависимости:** Flight/Participant/Attendance models, репозиторий, правила доступа.
- **Ошибки:** пустые/дублирующиеся записи, удаление участника с историей ответов.
- **Приёмка:** демоданные отделены; CRUD и статусы устойчивы после перезапуска; агрегаты вычисляются из списка.
- **Статус:** частично реализован; фиктивные имена/числа убраны из текущего экрана, локальный список имён и статусы на вылет отображаются; стабильных ID участников, редактирования/удаления/поиска и общей синхронизации пока нет.

### MSG-01 — Сообщения
- **Назначение:** подготовить, предварительно просмотреть и отправить объявление согласованным каналом.
- **Вход:** шаблон/текст, flightId, получатели, канал.
- **Выход:** запись отправки и результат по получателям.
- **Зависимости:** модель вылета, сервис доставки, сервер/бот.
- **Ошибки:** отмена chooser, недоступный канал, частичный отказ доставки.
- **Приёмка:** история показывает фактический результат; не сообщать об успехе до подтверждения канала.
- **Статус:** частично реализован; предпросмотр и системное «Поделиться», без массовой рассылки/истории.

### CAL-01 — Календарь
- **Назначение:** находить вылеты по дате и открывать карточку события.
- **Вход:** дата/диапазон и список вылетов.
- **Выход:** список соответствующих событий.
- **Зависимости:** Flight repository.
- **Ошибки:** пустой день, часовой пояс, изменённый/удалённый вылет.
- **Приёмка:** календарь отражает реальные записи вылетов.
- **Статус:** частично реализован; сохраняется выбранная дата, но полноценной модели событий нет.

### SET-01 — Настройки клуба
- **Назначение:** хранить общие параметры клуба.
- **Вход:** имя клуба, адрес по умолчанию, настройки.
- **Выход:** сохранённая конфигурация.
- **Зависимости:** ClubSettings repository.
- **Ошибки:** невалидные значения и конфликт настроек.
- **Приёмка:** настройки не перезаписывают данные конкретного вылета.
- **Статус:** частично реализован; место по умолчанию пока хранится как поле вылета.

### NTF-01 — Уведомления
- **Назначение:** напоминания и push-события по вылетам.
- **Вход:** событие/время, разрешения, токены устройств.
- **Выход:** реальный результат постановки/доставки уведомления.
- **Зависимости:** Android notifications, FCM, серверный отправитель.
- **Ошибки:** запрет разрешения, неверный токен, сеть/сервер недоступны.
- **Приёмка:** состояния и ошибки отображаются правдиво.
- **Статус:** не реализован; имеется информационный экран.

### MAP-01 — Маршрут
- **Назначение:** открыть карты по месту встречи.
- **Вход:** адрес или проверенные координаты.
- **Выход:** ACTION_VIEW intent.
- **Зависимости:** Android Maps Intent.
- **Ошибки:** приложение карт отсутствует, адрес не найден.
- **Приёмка:** запрос соответствует сохранённому месту; точность адреса проверена.
- **Статус:** частично реализован; используется текстовый запрос.

### SHR-01 — Системное «Поделиться» / Telegram
- **Назначение:** передать текст о вылете выбранному приложению.
- **Вход:** актуальная модель вылета.
- **Выход:** системный chooser.
- **Зависимости:** Android ACTION_SEND.
- **Ошибки:** нет подходящего приложения/пользователь отменил действие.
- **Приёмка:** в тексте актуальные данные; не обещать доставку.
- **Статус:** частично реализован; прямой Telegram API не подключён.

### AUTH-01 — Авторизация и роли
- **Назначение:** ограничить административные операции.
- **Вход:** учётная запись/сессия и роль.
- **Выход:** подтверждённая личность и разрешения.
- **Зависимости:** согласованный auth-сервис/API.
- **Ошибки:** истёкшая сессия, отказ доступа, недоступный сервер.
- **Приёмка:** права проверяются сервером.
- **Статус:** не реализован; админ-панель не защищена.

### DATA-01 — Хранилище и репозитории
- **Назначение:** единственная точка доступа к моделям и миграциям данных.
- **Вход:** команды чтения/записи.
- **Выход:** типизированные модели и результат операции.
- **Зависимости:** локальная БД и/или API.
- **Ошибки:** повреждение/недоступность данных, миграции.
- **Приёмка:** UI не читает SharedPreferences напрямую; у каждой сущности один источник истины.
- **Статус:** частично реализован; вылеты проходят через FlightRepository, но участники и ответы проходят через AttendanceRepository; участники пока читаются/пишутся напрямую из Activity.

### SYNC-01 — Серверная синхронизация
- **Назначение:** синхронизировать вылеты, участников, ответы и сообщения между устройствами.
- **Вход:** локальные изменения, API-ответы и версии записей.
- **Выход:** согласованное состояние.
- **Зависимости:** серверный API, AUTH-01, DATA-01.
- **Ошибки:** конфликт версий, офлайн, повтор запроса.
- **Приёмка:** два устройства видят согласованные данные; повтор запроса безопасен.
- **Статус:** не реализован; API не указан.

### LOG-01 — Журнал событий
- **Назначение:** диагностика важных операций и ошибок.
- **Вход:** событие, время, модуль, результат и безопасный контекст.
- **Выход:** локальный/серверный журнал.
- **Зависимости:** logging adapter.
- **Ошибки:** переполнение, недоступность хранилища.
- **Приёмка:** есть след ошибок и операций; нет секретов и лишних персональных данных.
- **Статус:** не реализован.

### QA-01 — Тестирование и выпуск
- **Назначение:** проверять поведение, сборку и происхождение APK.
- **Вход:** commit SHA и тестовые сценарии.
- **Выход:** результат тестов, артефакт и отчёт.
- **Зависимости:** GitHub Actions, Android SDK, JDK/Gradle.
- **Ошибки:** failed workflow, отсутствие APK/артефакта, несовпадение SHA.
- **Приёмка:** успешный CI именно для проверяемого SHA; ключевые сценарии проверены.
- **Статус:** частично реализован; workflow существует, каждый актуальный запуск проверяется отдельно.

- [ ] Проверено, что аналогичной реализации уже нет.
- [ ] Не нарушен утверждённый дизайн.
- [ ] Реальная функция не подменена демо-экраном.
- [ ] Обновлены паспорт и ТЗ при необходимости.
- [ ] Добавлены/обновлены проверки.
- [ ] Проверен актуальный CI и SHA.
- [ ] README отражает текущие ограничения.
