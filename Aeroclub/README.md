## Отладка модулей

Единый локальный журнал, ротация файла, измерение времени операций и ручной экспорт через системное меню «Поделиться» описаны в [MODULE_DEBUGGING.md](MODULE_DEBUGGING.md). Секреты не встраиваются в APK; прямая загрузка в GitHub отключена, так как безопасный серверный посредник запрещён текущим локальным режимом.

# Аэроклуб — информер Android

> **Перед любой работой сначала прочитать [TASK_REGISTRY.md](TASK_REGISTRY.md), затем [SCREEN_MAP.md](SCREEN_MAP.md).** Все дефекты сначала фиксируются в реестре задач; экраны обсуждаются по постоянным ID.

Android-приложение с главным экраном-календарём. Даты с мероприятиями отмечены красным; нажатие открывает карточку с названием, датой/временем, местом встречи и четырьмя действиями: «Я поеду», «Я не поеду», «Маршрут», «Telegram». Домашний виджет W01 должен быть заменён новой реализацией по оригиналу `design/dezign.jpg`; он существует параллельно с главным экраном приложения S01 — календарём.

## Сборка
- Android Gradle Plugin 8.6.1
- Gradle 8.7
- JDK 17
- compileSdk 35
- APK собирается GitHub Actions в отдельной ветке `aeroclub-informer`.

## Реализовано
- Главный экран-календарь с переключением месяцев и красными датами мероприятий.
- Карточка выбранного мероприятия с четырьмя действиями.
- Локальное сохранение ответа «Я еду» / «Я не еду» с привязкой к активному вылету и стабильному локальному ID устройства (до подключения авторизации).
- «Маршрут» открывает поиск места встречи в приложении карт.
- «Telegram» открывает системное меню отправки текста о ближайшем вылете.
- Локальная панель администратора: обзор, вылеты, участники, сообщения, календарь, настройки и состояние уведомлений.
- Администратор может создавать, редактировать, удалять и выбирать активный вылет из локального списка; изменения отражаются в календаре и карточке мероприятия.
- Для вылета можно хранить локальную отметку публикации/черновика; эта отметка не публикует данные на сервере.
- `:core:data` использует единый приватный JSON-файл `aeroclub-local-data.json` через `LocalFilePreferences`; при первом запуске значения старого `SharedPreferences` `flight_informer` мигрируют без удаления исходного файла. Репозитории вылетов, участников, ответов, календаря, настроек, журнала и истории используют этот общий файл.
- Участники имеют стабильные локальные ID; доступны поиск, добавление, переименование, удаление и статусы по каждому вылету.
- Старые записи участников мигрируют из прежнего строкового формата.
- Ответы администраторского списка и ответы из информера проходят через AttendanceRepository.
- Для сообщений есть три шаблона, предпросмотр, сохранение черновиков, загрузка текста из истории и локальная история; открытие меню отправки не считается доставкой.
- Общие настройки клуба вынесены в ClubSettingsRepository.
- `SyncRepository` отключён как серверная очередь в локальном режиме: операции не копятся в фиктивный outbox, изменения сохраняются в локальном JSON-файле.
- Журнал последних 200 технических событий доступен из раздела уведомлений.
- Локальные напоминания ставятся за 1 час до будущего вылета через AlarmManager. Расписание пересчитывается после сохранения и удаления вылета, восстанавливается после перезагрузки и перепланируется после изменения системных даты, времени или часового пояса. Канал использует `vario_climb.wav` и вибрацию; фактическое воспроизведение звука необходимо проверить на реальном устройстве. Запись звука с микрофона в ТЗ информера не предусмотрена. Push через FCM пока не подключён.

- Экспорт списка участников и статусов через системное меню «Поделиться».
- Календарь выводит сохранённые вылеты по полной ISO-дате, не смешивая одинаковые числа разных лет.
- Сводка участников считается по локальным записям, без фиктивных чисел и демонстрационных имён.
- Настройка места встречи по умолчанию отделена от места конкретного вылета.

## Важные ограничения прототипа
Название, дата, время и адрес по умолчанию демонстрационные. Маршрут ищется по текстовому адресу, а не по подтверждённым координатам. Ответы и добавленные участники хранятся только на этом устройстве. Ответы локального устройства привязаны к ID вылета и локальному ID участника; это не полноценная учётная запись, ответы не синхронизируются между устройствами. Список участников состоит из локально добавленных записей и не является общей базой клуба. Нет работающей серверной синхронизации (серверная очередь отключена), контактных полей, массовой отправки сообщений, авторизации администратора и FCM-push. Локальные напоминания зависят от разрешения Android и требуют проверки на реальном устройстве. Кнопка «Telegram» открывает системное меню отправки текста, а не гарантирует доставку в Telegram. Эти функции нельзя считать готовыми до подключения API клуба, безопасной авторизации и серверной инфраструктуры.

## Gradle-модули

- `:core:common` — доменные модели, канонические статусы ответов, единое форматирование метки DEMO и валидация ISO-даты/времени без Android-зависимостей; добавлены unit-тесты.
- `:core:data` — единый локальный JSON-файл, репозитории и миграция прежних данных.
- `:core:ui` — общие цвета, UI-токены и форма карточек.
- `:core:android` — единый адаптер маршрута/share.
- `:feature:notifications` — локальные напоминания, восстановление после перезагрузки и единая `NotificationSoundPolicy` для сигнала вариометра набора высоты (`res/raw/vario_climb.wav`) и вибрации напоминаний. Звук входящих сообщений не включён: реального входящего источника пока нет.
- `:feature:admin-flights` — сценарии создания, изменения и удаления вылетов.
- `:feature:admin-participants` — сценарии участников и ответов.
- `:feature:calendar` — выбор ISO-даты и фильтрация вылетов по дате.
- `:feature:messages` — шаблоны сообщений, локальное файловое хранилище/транспорт и foreground-наблюдение за изменениями; админ-панель и информер используют единую точку выбора транспорта `MessageTransportProvider`. Удалённая доставка и реальные входящие сообщения не подключены.
- `:feature:settings` — сценарии настроек клуба.
- `:feature:admin` — экран администратора и его текущие разделы.
- `:feature:informer` — главный календарь, карточка мероприятия и действия участника.
- `:app` — Android-манифест и сборка; виджет удалён.
- Сгенерированная демонстрационная запись явно помечается `ДЕМО` в календаре/карточке мероприятия и системном меню «Поделиться»; это не общие данные клуба.

Экран информера вынесен в `:feature:informer`, экран разделов админ-панели вынесен в `:feature:admin`, но разделы пока остаются в одном `AdminActivity`; use-case модули этих функций выделены; экранные UI-компоненты всё ещё собраны в одном `AdminActivity`. API, авторизация, реальная синхронизация и FCM заблокированы отсутствием согласованного сервера/конфигурации. CI сборка теперь запускается вручную и при запуске выполняет unit-тесты перед сборкой APK.


## Диагностика и отправка логов

Описание логирования, автоматической отправки в GitHub и настройки токена: [MODULE_DEBUGGING.md](MODULE_DEBUGGING.md).

### Локальное хранение на одном устройстве

- Каноническое хранилище доменных данных: приватный файл приложения `aeroclub-local-data.json`.
- Старые данные `flight_informer` переносятся в JSON при первом создании файла; исходные SharedPreferences не удаляются.
- Локальные сообщения транспорта находятся отдельно в `local_message_transport/messages.json`; это локальные записи, а не удалённые входящие сообщения.
- Сервер, FCM, авторизация и синхронизация между устройствами в этом режиме не используются.
- Контрольная сборка после перехода на единый файл ещё не выполнена; готовность механизма должна быть подтверждена итоговыми тестами и запуском на устройстве.


### Прототип файлового обмена сообщениями
На главном экране доступны «Экспортировать файл сообщений» и «Импортировать файл сообщений». Android открывает системный выбор места сохранения/источника файла; используется JSON-формат `aeroclub-message-exchange`, версия 1. Импорт сначала проверяет формат и записи, затем объединяет их с локальной историей по уникальному ID, не создавая повторов. Файл можно вручную перенести на другое устройство и импортировать там. Это не автоматическая доставка сообщений и не общая синхронизируемая база; импортированные объявления остаются локальными. Повреждённый/неподдерживаемый файл отклоняется без намеренного сброса текущей истории.
