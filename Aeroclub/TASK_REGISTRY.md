# Реестр задач — Aeroclub Informer

**Правило:** этот файл — первый документ, который ИИ читает перед любой работой над Aeroclub. Не начинать изменение кода, пока не проверены верхние незакрытые задачи и их критерии приёмки. Не удалять закрытые задачи и не менять порядок приоритетов без причины; новые критические дефекты добавлять сверху. После каждого изменения обновлять статус, commit SHA, проверку и остаток. Задачи пользователя записаны как требования, а не как утверждение, что они уже исправлены.

Обновлено: 2026-10-21. Ветка: `aeroclub-informer`.

## P0 — блокирующие дефекты текущей сборки

### AERO-001 — Устранить конфликт Android-пакета
- **Статус:** IN PROGRESS / BLOCKER
- Код: applicationId изменён на `ru.aeroclub.informer.mobile`, чтобы отделить APK от старого пакета/подписи. Подтвердить CI и установку на устройстве.
- **Симптом:** Android сообщает, что приложение конфликтует с другим пакетом.
- **Работа:** проверить `applicationId`, подпись APK, установленную версию и package ID конфликтующего приложения; определить, конфликтует ли другое приложение с тем же package ID или несовместима подпись обновления.
- **Важно:** не менять package ID наугад — это может создать второе приложение и потерять ожидаемый путь обновления.
- **Приёмка:** APK устанавливается как новая установка; сценарий обновления проверен отдельно; package ID и подпись указаны в build manifest.

### AERO-002 — Починить загрузку/добавление виджета
- **Статус:** IN PROGRESS / BLOCKER
- **Критическое требование размера (зафиксировано 2026-10-22):** W01 — компактный виджет шириной **2 ячейки сетки домашнего экрана, не 4**. Не путать размер внешнего виджета с сеткой 2×2 для четырёх кнопок. Четыре действия должны помещаться внутри без наложений.
- Код: карточка виджета открывает информер; четыре действия сохранены; системное обновление — 30 минут; добавлено принудительное обновление установленных виджетов после перезапуска/смены даты или времени. Проверить добавление и перезапуск на устройстве.
- **Экран:** S01 (приложение/информер) + W01 (домашний виджет).
- **Работа:** проверить AppWidgetProvider, layout, updatePeriod/initialLayout, RemoteViews и обработчики кнопок; проверить первый запуск, добавление на домашний экран и обновление после изменения активного вылета.
- **Приёмка:** виджет добавляется на главный экран, отображает актуальный вылет и все четыре действия, обновляется после изменения данных и не исчезает после перезапуска телефона.

### AERO-003 — Упростить адресацию сообщений
- **Статус:** IN PROGRESS
- Код: добавлен выбор «Всем / Одному участнику / Группе»; выбор участника/группы вычисляет локальный состав адресатов, показывает количество и имена в тексте-подготовке. Пустая группа блокирует открытие меню передачи. Серверная доставка не реализована.
- **Экран:** S04 — Сообщения.
- **Требование UI:** простой выбор адресата из трёх вариантов: **Всем**, **Одному участнику**, **Группе**.
- **Работа:** для «Одному» показывать выбор одного участника; для «Группе» — выбор сохранённой группы/состава; для «Всем» не требовать выбора участника. Отображать выбранного адресата явно перед подготовкой/отправкой.
- **Ограничение:** в локальном прототипе не изображать сообщение доставленным. Реальная отправка/доставка остаётся заблокированной отсутствием серверного канала/контактов.

### AERO-004 — Доработать календарь и навигацию
- **Статус:** IN PROGRESS
- Код: календарная сетка, переключение месяцев, выбор даты, отметки дат с вылетами и переход к подготовке сообщения. Навигация теперь хранит историю экранов: «Назад» возвращает на предыдущий экран, а не всегда в обзор.
- **Экран:** S05 — Календарь.
- **Работа:** добавить видимый возврат назад/к предыдущему экрану; показать настоящий календарь с переходом между месяцами и отметками дат вылетов; выбор даты должен показывать вылеты выбранного дня.
- **Диалог с клиентом:** добавить понятный поток просмотра/подготовки сообщения, связанный с выбранным вылетом и выбранным адресатом, без имитации реальной доставки.
- **Приёмка:** пользователь видит календарную сетку, меняет месяц, выбирает дату, видит связанные вылеты, возвращается назад и может перейти к сообщению с контекстом выбранного вылета.

### AERO-005 — Единая визуальная реакция кнопок
- **Статус:** IN PROGRESS
- Код: custom-кнопки админ-панели и календаря используют RippleDrawable; виджет использует стандартные Android Button.
- **Область:** все интерактивные кнопки приложения и виджета, где Android это позволяет.
- **Требование:** при касании кнопка сразу визуально меняет состояние (ripple/pressed/selected/disabled по смыслу); состояние не должно зависать после завершения действия. Сохранить стандартный Android-дизайн и доступность.
- **Приёмка:** визуально проверены основные, навигационные, диалоговые и кнопки виджета; нет кнопок без обратной связи.

### AERO-006 — Автоматический файл обмена данными о полётах в Downloads
- **Статус:** IN PROGRESS / BLOCKER
- Код: `FlightDownloadExchange` автоматически публикует `Download/Aeroclub_Informer_flights.json`, импортирует изменённый файл по SHA-256, проверяет схему и уникальность ID. Информер/админ-панель опрашивают файл раз в 5 секунд в foreground.
- **Папка/имя:** Android `Download/Aeroclub_Informer_flights.json`.
- **Требование:** приложение само сохраняет актуальные данные о полётах в этот файл и само читает его для обновления информера/виджета. Не требовать ручного экспорта/импорта в обычном потоке.
- **Работа:** определить единый JSON schema/version; атомарная/безопасная запись; чтение при запуске и возврате приложения; обработка изменения файла; защита от циклической перезаписи, дублей и повреждённых данных; согласовать, кто является источником истины, чтобы внешний файл и внутренний репозиторий не затирали изменения друг друга. На Android 10+ использовать MediaStore/SAF в соответствии с ограничениями Android; ошибки доступа явно отображать и журналировать.
- **Приёмка:** файл появляется в Downloads без ручного действия; содержит текущие вылеты; после изменения файла информер и виджет обновляются; после перезапуска данные не теряются; повторное чтение не создаёт дубли; отказ доступа не выдаётся за успех.
