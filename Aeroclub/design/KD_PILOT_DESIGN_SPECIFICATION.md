# KD PILOT — полная спецификация дизайна экранов и компонентов

Дата фиксации: 2026-11-21  
Ветка: `aeroclub-informer`  
Статус: **рабочая спецификация; не является подтверждением визуального соответствия APK**  
Приоритет: **P0 — типографика → геометрия → поверхности/декор → состояния**.

## 0. Назначение, источники и правила достоверности

Документ задаёт построчную структуру интерфейса KD PILOT для каждого ID из `SCREEN_MAP.md`, а также порядок измерения и приёмки. Он предназначен для реализации и визуальной проверки, а не для замены оригинальных макетов.

Источники истины:
1. Оригинальные изображения/board в `Aeroclub/design/` и ранее переданные пользователем макеты: `dezign.jpg`, `content.png`, `1000067827.jpg`, экран «Все полёты аэроклуба».
2. `SCREEN_MAP.md` — назначение экранов и навигация.
3. `DESIGN_REFERENCE.md`, `CSS_DESIGN_SPECIFICATION.md`, `STYLE_CALIBRATION.md`.
4. `KD_PILOT_TYPOGRAPHY.md` — исходные параметры типографики S12.
5. Текущие Android-исходники — только источник сведений о фактической реализации, но не автоматический эталон дизайна.

Обозначения достоверности:
- **ЗАФИКСИРОВАНО** — значение прямо записано в доступной спецификации/исходном анализе.
- **ТРЕБУЕТ ИЗМЕРЕНИЯ** — значение нельзя достоверно получить из текстовых документов; его необходимо измерить по оригинальному изображению.
- **ТРЕБУЕТ ПОДТВЕРЖДЕНИЯ** — смысл/состояние описан картой экранов, но точное визуальное решение макетом ещё не подтверждено.
- **НЕ ПРИМЕНЯЕТСЯ** — элемент отсутствует на данном экране.

Запрещено подставлять «примерные» размеры и выдавать их за измеренные. Все координаты исходного board ведутся в координатной системе оригинала; пересчёт в Android dp выполняется только после фиксации размера viewport, density, fontScale и safe areas.

## 1. Главный принцип: шрифт — несущий каркас

Порядок проектирования каждого экрана:
1. Семейство шрифта и реальные файлы начертаний.
2. Вес/начертание каждого текстового стиля.
3. Кегль и фактическая ширина глифов, особенно кириллицы.
4. Baseline, высота строки, межстрочный интервал, letter spacing.
5. Переносы и обрезка длинных строк.
6. Геометрия текстовых блоков и высоты строк.
7. Геометрия карточек, панелей, кнопок и навигации.
8. Иконки, границы, тени, градиенты и прочие декоративные детали.

Не корректировать геометрию случайными сдвигами, пока не стабилизирована типографика.

Зафиксировать источник, версию, лицензию и SHA-256 выбранного файла.

### 1.2 Метрики текста, обязательные для каждого стиля

Для каждой конкретной надписи измерить: font family, font weight, font size, line-height, baseline Y, высоту видимых глифов, ширину строки, letter spacing, цвет, alignment, maxLines, перенос, ellipsize и внутренние отступы контейнера. Проверять реальные строки из макета, не абстрактный lorem ipsum.

## 2. Общая визуальная система

### 2.1 Цветовые токены

| Токен | Значение | Применение |
|---|---|---|
| color.primary | #0066FF | основные действия, активные вкладки/навигация |
| color.success | #00C853 | положительное действие/статус, если это соответствует эталону |
| color.danger | #FF3B30 | отрицательное действие/статус, если это соответствует эталону |
| color.surface | #FFFFFF | карточки и поверхности |
| color.background | #F5F7FA | фон S12 по анализу |
| color.text.primary | #1F2937 | основной текст |
| color.text.secondary | #9CA3AF | вторичный текст |
| color.divider | #E5E7EB | разделители |
| color.shadow | 0 2px 8px rgba(0,0,0,.05) | карточки S12 по анализу |

Палитра S12 не переносится автоматически на остальные экраны, если их оригинальный board показывает другое. Цвета статусных плашек, верхней панели администратора и фона остальных экранов — **ТРЕБУЕТ ИЗМЕРЕНИЯ** по соответствующей части оригинала.

### 2.2 Геометрическая база

- Для анализа S12 зафиксирована ширина board 1024 px и высота около 2334 px; сетка калибровки 10 px.
- Уточнить точный размер и обрезку оригинала перед измерениями.
- Не смешивать исходные px, CSS px, физические пиксели скриншота и Android dp.
- Зафиксировать Android viewport, density, fontScale, status bar, navigation bar и safe insets.
- Для каждого компонента записывать bounding box: x, y, width, height; отдельно — padding, margin/gap, radius, border, elevation/shadow.
- Системные status/navigation bars оставлять системными, если макет не требует иного; не рисовать их копии внутри приложения.

### 2.3 Карточки, кнопки, иконки и слои

Для каждой карточки отдельно измерить внешний прямоугольник, радиус каждого угла, внутренние отступы, фон, границу, тень, порядок слоёв и clipping. Не назначать общий радиус всем карточкам по умолчанию.

Для каждой кнопки отдельно измерить высоту/ширину, форму, цвет, border, иконку, расстояние и выравнивание текста, pressed/focused/disabled/selected состояния. Для каждой иконки фиксировать источник, viewBox/размер, толщину штриха, оптический размер, baseline и цвет. Символьные Unicode-иконки из текущего прототипа не являются эталоном, если в оригинале используются графические пиктограммы.

## 3. Построчная спецификация экранов

## W01 — виджет KD PILOT на домашнем экране Android

**Эталон:** `Aeroclub/design/dezign.jpg`.  
**Назначение:** домашний виджет-информер; целевая ширина — две ячейки лаунчера. Сам виджет не равен сетке из четырёх внутренних действий.

Порядок элементов сверху вниз:

1. **W01-01 — внешний контейнер виджета.** Форма, размер, фон, радиус, тень, прозрачность, внутренние поля и clipping — ТРЕБУЕТ ИЗМЕРЕНИЯ по dezign.jpg. Фактическую ширину в ячейках проверить на launcher отдельно.
2. **W01-02 — шапка/бренд KD PILOT.** Логотип и надпись; тип, начертание, размер, baseline, цвет, отступы — ТРЕБУЕТ ИЗМЕРЕНИЯ.
3. **W01-03 — индикатор статуса.** Текст статуса «Сегодня полёты» (если соответствует конкретному состоянию макета), форма, цвет, точка/иконка, размеры и положение — ТРЕБУЕТ ИЗМЕРЕНИЯ.
4. **W01-04 — аэродром/место.** Текст места, размер, вес, перенос/обрезка и пиктограмма — ТРЕБУЕТ ИЗМЕРЕНИЯ.
5. **W01-05 — время в верхней зоне.** Формат, шрифт, размеры и выравнивание — ТРЕБУЕТ ИЗМЕРЕНИЯ.
6. **W01-06 — индикатор сообщения.** Иконка конверта/сообщения и бейдж непрочитанного: размеры, число, фон, радиус и позиция — ТРЕБУЕТ ИЗМЕРЕНИЯ. Ноль не должен имитировать входящие сообщения.
7. **W01-07 — шкала вариометра.** Полоса/сегменты, красная/нейтральная/зелёная зоны, центральная точка, отметки −3…+3; все ширины, высоты, цвета, промежутки и шрифт отметок — ТРЕБУЕТ ИЗМЕРЕНИЯ.
8. **W01-08 — крупные цифровые часы.** Текст времени, семейство/вес/кегль, baseline, межцифровые интервалы и выравнивание — ТРЕБУЕТ ИЗМЕРЕНИЯ.
9. **W01-09 — дата.** Формат, регистр, шрифт, цвет и положение относительно часов — ТРЕБУЕТ ИЗМЕРЕНИЯ.
10. **W01-10 — нижняя группа действий 2×2.** Четыре действия: «Я еду», «Я не еду», «Маршрут», «Telegram». Каждая кнопка описывается отдельно: размер, положение, фон, радиус, иконка, текст, gap и pressed-состояние — ТРЕБУЕТ ИЗМЕРЕНИЯ. Сохранить настоящие маршруты действий и подтверждение маршрута.
11. **W01-11 — графика/декор.** Горный фон, линии, текстуры и градиенты включать только если они реально присутствуют в оригинале; размеры/цвета/слои — ТРЕБУЕТ ИЗМЕРЕНИЯ.

Состояния W01: обычное; нет ближайшего полёта; полёт сегодня; сообщение отсутствует/есть; нажатие каждой из четырёх кнопок; недоступное внешнее приложение; пустое место встречи. Данные и счётчики не выдумывать.

## 4. Сквозные компоненты и состояния

### 4.1 Верхняя панель
Для каждого экрана отдельно сверить высоту, цвет, title/subtitle, кнопку назад, домашний переход, отступы и системную status bar. Не копировать параметры S02 на S12 или наоборот.

### 4.2 Нижняя навигация
Четыре пункта, если они предусмотрены соответствующим экраном: иконка, подпись, зона касания, active/inactive, pressed/focused. Сами пункты ведут к согласованным экранным ID; активный пункт отражает фактический экран. Проверить нижнюю safe area и то, что контент не перекрывается панелью.

### 4.3 Карточки
Карточки разных ролей/экранов могут иметь разные композиции. Для каждой измерить отдельно: фон, границу, тень, радиус, ширину, padding, вертикальный ритм, заголовок, метаданные, действия и selected state.

### 4.4 Диалоги
Проверить dim amount, ширину окна, вертикальное центрирование, скругления, кнопки, порядок фокуса, закрытие по Back/вне окна и сохранение контекста.

### 4.5 Прокрутка
Для каждого scroll container определить верхнюю и нижнюю границы, закреплённые элементы, inset, высоту viewport, fling/overscroll и поведение при открытой клавиатуре. Нижняя навигация и верхняя панель не должны случайно прокручиваться вместе с основным контентом, если оригинал фиксирует их.

### 4.6 Состояния доступности
Минимум: default, pressed, focused, selected, disabled, loading, empty, error, long text, keyboard open, system font scale increase. Контраст и hit area проверять отдельно от пиксельного сходства.

## 7. Алгоритм измерения и реализации

1. Открыть оригинальный файл макета, проверить его SHA-256 и разрешение; не изменять оригинал.
2. Зафиксировать viewport и координатную сетку.
3. Для каждого экрана построить таблицу элементов с bbox и текстовыми метриками.
4. Сначала откалибровать шрифты и реальные строки.
5. Зафиксировать font assets и токены.
6. Исправить общий каркас и размеры контейнеров.
7. Исправить карточки/строки/кнопки.
8. Исправить иконки, границы, тени и фон.
9. Реализовать состояния и адаптацию без потери целевого вида.
10. Собрать APK из фиксированного commit SHA.
11. Запустить UI acceptance на аппаратно ускоренном эмуляторе. Проверить KVM/ускорение/backend; не считать SwiftShader эквивалентом аппаратного ускорения.
12. Получить скриншот каждого экрана и каждого важного состояния.
13. Сравнить в одном viewport/density/fontScale: overlay 50%, difference image, SSIM/MAE (как вспомогательные метрики), отдельная текстовая маска и ручная проверка.
14. Исправлять самые крупные области расхождения; повторять сборку/запуск/сравнение.
15. Проверить навигацию и реальные данные отдельно от визуальной приёмки.
16. Сохранить исходные скриншоты, overlay, diff, логи, build SHA и результат каждого цикла в проекте.
