# KD PILOT — дизайн-аудит и порядок исправления экранов
Дата: 2026-11-21
Ветка: `aeroclub-informer`
Основание: переданные пользователем эталоны `Все полёты аэроклуба.png`, `content.png`, `1000067827.jpg`, а также `SCREEN_MAP.md`.

## 1. Что является эталоном
- S12 — главный экран участника «Все полёты»: отдельный список карточек предстоящих полётов.
- S01 — отдельный календарь участника. Не подменять его S12.
- S02 — административный обзор; не подменять им S12 или S01.
- S03–S08 — отдельные разделы администратора.
- Экранный board `content.png` задаёт общую визуальную систему: синяя верхняя панель, светлый фон, карточки, единая нижняя навигация. Каждый экран board остаётся отдельным экраном, а не одной длинной страницей.
- `1000067827.jpg` — координатная разметка главного списка; использовать для проверки геометрии, но не как отдельный дизайн.

## 2. Зафиксированная структура S12
1. Системная строка состояния Android остаётся системной.
2. Верхняя область приложения: логотип/название «Аэроклуб» слева; «Создать полёт» справа и только для роли, которой разрешено создание.
3. Переключатель вкладок: «Все полёты» / «Соревнования».
4. Вертикальный прокручиваемый список карточек полётов.
5. Карточка: дата; время; место/аэродром; один сводный статус ответа; переход в подробности; аватары/счётчики — только если они реально доступны из локальных данных.
6. Нижняя навигация: «Главная» / «Участники» / «Календарь» / «Настройки».
7. Нижняя навигация закреплена и не прокручивается вместе со списком; список занимает только промежуточную область.

## 3. Критические правила логики экранов
- Нажатие на карточку открывает подробности именно выбранного полёта; все действия в карточке подробностей используют его ID, а не ближайший/активный полёт по умолчанию.
- Вкладка «Соревнования» фильтрует только соревнования; возврат на «Все полёты» сохраняет ожидаемую позицию/состояние списка.
- «Календарь» ведёт на S01, а не на админ-календарь S05.
- «Участники» ведёт на S06; «Настройки» — на S07. Не оставлять навигационные элементы без работающего назначения.
- «Создать полёт» доступно только разрешённой роли и ведёт в существующий сценарий S03/редактор, без второго независимого хранилища.
- Ответы, числа участников и статусы нельзя выдумывать. Локальные данные явно остаются локальными; не имитировать общеклубную статистику.
- Системная кнопка Back возвращает на предыдущий ожидаемый экран и не теряет черновик без подтверждения.

## 4. Визуальные критерии по переданному S12
- Светлый холодный фон, тёмно-синяя основная типографика, насыщенный синий для главного действия и выбранной навигации.
- Карточки имеют заметные скругления, тонкую границу/мягкую тень и достаточное внутреннее пространство.
- Сводный статус визуально различим: зелёный «Едут», красный «Не едут», нейтральный серо-синий «Нет ответа».
- Строки даты, времени и места выровнены по общей вертикали; пиктограммы одного оптического размера.
- Карточки имеют одинаковую систему внутренних отступов и межстрочных интервалов; статус не должен перекрывать дату/место на узких экранах.
- Аватары допускаются только при наличии изображений участников. Иначе показывать нейтральное количество/текст без фиктивных лиц.
- Нижняя навигация имеет четыре равномерно распределённых пункта, иконку над подписью и ясное выбранное состояние.

## 5. Порядок автономной переработки
1. Получить реальные скриншоты S12, S01, S02–S08 из UI acceptance на эмуляторе с аппаратным ускорением.
2. Для каждого экрана сверить дерево контейнеров, геометрию, цвета, типографику, отступы и состояния с соответствующей частью board.
3. Исправлять сначала общий каркас: тему, верхнюю область, нижнюю навигацию, размеры/прокрутку контента.
4. Затем исправлять карточки и отдельные компоненты; после каждого блока повторять UI screenshot test.
5. После визуальной приёмки отдельно проверить переходы и действия по ID выбранного полёта.
6. Не отмечать экран принятым, пока не сохранены скриншот и результат UIAutomator/логов.

## 6. Проверка аппаратного ускорения
Workflow `.github/workflows/build-aeroclub-informer.yml` настроен на runner `macos-15-intel`, проверку `emulator -accel-check` и запуск Android Emulator с `-gpu host`. UI acceptance запускает `Aeroclub/scripts/ui_acceptance.py`, сохраняет скриншоты и logcat. Сборка/юнит-тесты не заменяют UI acceptance. Если шаг UI не выполнен или ускорение недоступно, результат считается НЕ ПРОВЕРЕНО, а не PASS.

## 7. Открытые пункты
- Реальные скриншоты текущего S12/S01/S02–S08 ещё должны быть проверены после нового прогона.
- Визуальное соответствие каждому экрану не подтверждено.
- Работоспособность всех переходов нижней навигации должна быть проверена отдельно.
- Этот документ фиксирует критерии и последовательность, но сам по себе не означает, что исходники UI уже исправлены.
