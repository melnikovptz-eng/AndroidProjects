# PMCA — Project Contract

Version: 0.2.0
Build label: 3

## Главный принцип

PmcaController — центральная точка управления выполнением.

Каждый модуль отвечает за одну обязанность.
Модули взаимодействуют через определённые интерфейсы.
Изменения связанных модулей согласуются вместе.

## Целевой поток

INPUT
 -> Controller
 -> Parser
 -> DuplicateGuard
 -> ProcessingGate
 -> ExecutionQueue
 -> ModuleRouter
 -> Module
 -> ResultManager
 -> StateManager
 -> Logger
 -> OUTPUT

## Каналы Termux

1. RUN_COMMAND API с callback через TermuxResultService.
2. Файловый JSON-мост:
   command.json -> Termux -> result.json.

Оба канала сохраняются до завершения тестирования.
Один запуск не должен случайно исполняться дважды.

## Требования к результату

- Уникальный execution ID / operation ID.
- Проверка соответствия результата операции.
- Разделение запуска, выполнения и получения результата.
- Явные состояния SUCCESS, ERROR, TIMEOUT, REJECTED.
- Защита от повторной обработки результата.
- Сохранение и отображение stdout, stderr и exit code.
- Версия и build label в диагностическом выводе.

## Ограничения

- Не удалять существующие адаптеры без проверки зависимостей.
- Не менять package name без необходимости.
- Не удалять пользовательские данные и резервные копии.
- Не считать принятие команды подтверждением успешного выполнения.
- Не создавать несколько конкурирующих очередей выполнения.
