# HANDOFF — ИНСТРУКЦИЯ ДЛЯ СЛЕДУЮЩЕГО ИИ

Прочитай этот файл перед продолжением разработки.

## 1. Не начинай с повторного исследования

Сначала прочитай:
- README.md
- PROJECT_PASSPORT.md
- CURRENT_STATE.md
- PROJECT_CONTRACT.md
- ARCHITECTURE.md
- MODULE_REGISTRY.md
- CLIPBOARD_AUTOCOPY_SPEC.md
- DECISIONS.md

Не запускай серию диагностических тестов только для ознакомления.
Не проверяй повторно размеры сообщений, если нет признаков обрезания.

## 2. Главный приоритет

Обеспечить автоматическое копирование результатов на всём пути:
вход -> обработка -> модуль -> контроллер -> результат -> буфер обмена.

Ближайшая архитектурная цель — выделенный ClipboardCopyModule.

## 3. Единственная активная реализация

Для каждой функции разрешён только один активный исполнитель.

При замене модуля:
1. Сохранить старую реализацию и резервную копию.
2. Подготовить новую реализацию.
3. Подключить её через центральный контроллер.
4. Проверить конкретную функцию.
5. Отключить старый исполнитель этой функции.
6. Убедиться, что старый путь не запускается параллельно.
7. Обновить MODULE_REGISTRY.md.
8. Записать решение в DECISIONS.md.
9. Обновить CHANGELOG.md и CURRENT_STATE.md.

Не делать незаметного отката на старую реализацию.
При отказе записать ошибку и сохранить диагностические сведения.

## 4. Не разрушай рабочее состояние

- Не удаляй старые проекты.
- Не выполняй массовую очистку.
- Не убивай все процессы Termux.
- Не создавай второй демон.
- Не перезаписывай занятый command.json.
- Не удаляй result.json без сохранения нужного результата.
- Перед правками рабочего скрипта создавай резервную копию.
- Не переписывай мост, если задача решается подключением нового модуля.

## 5. Стиль работы

Предпочтителен один цельный исполняемый скрипт.
Вывод должен содержать понятные этапы.
Копирование результата в буфер должно быть ограничено по времени.
В конце выводить:
===== ГОТОВО — ОТПРАВЬ РЕЗУЛЬТАТ =====

## 6. Перед завершением каждой значимой задачи

Зафиксировать:
- что изменено;
- где находится файл;
- какая реализация теперь активна;
- какая старая реализация отключена;
- что проверено;
- что осталось сделать;
- какие резервные копии созданы.

Не называть функцию готовой, если создан только файл, но он не подключён.
