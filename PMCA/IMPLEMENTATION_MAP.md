# PMCA — Implementation Map

## 1. Назначение документа

Документ описывает фактическую структуру исходного кода PMCA,
известные связи между компонентами и степень подтверждения реализации.

**Правило:** наличие класса или метода само по себе не означает,
что функция полностью интегрирована или проверена на устройстве.

Целевая архитектура описывается в `ARCHITECTURE.md`.
Фактическая реализация описывается здесь.

## 2. Источники сведений

- Инвентаризация исходного кода: `~/PMCA_IMPLEMENTATION_MAP.txt`
- Исходный код приложения: `AndroidBridge/app/src/main/java/com/pmca/bridge/`
- Мост Termux: `~/TaperV6/termux_bridge_daemon.sh`
- Собранное приложение: `~/storage/downloads/PMCA.apk`

Карта создана на основе статического аудита. Она не заменяет
функциональные испытания установленного приложения.

## 3. Значение статусов

| Статус | Значение |
|---|---|
| PRESENT | Компонент найден в исходном коде |
| ACTIVE | Участие в рабочем сценарии подтверждено |
| VERIFIED | Конкретный сценарий успешно проверен |
| PLANNED | Функция предусмотрена планом, реализация не подтверждена |
| UNKNOWN | Данных недостаточно для вывода |

Статусы относятся к конкретному компоненту или сценарию, а не ко всему проекту.

## 4. Карта компонентов

### 4.1. Главное окно

**Файл:** `AndroidBridge/app/src/main/java/com/pmca/bridge/MainActivity.java`

Назначение:
- создание основного пользовательского интерфейса;
- ввод и отправка команд;
- отображение статуса и журнала;
- работа с плавающей панелью;
- обработка результатов Termux;
- процедуры установки APK.

Статус: `PRESENT`.

Примечание: отдельные сценарии интерфейса требуют проверки на устройстве.

### 4.2. Центральный контроллер

**Файл:** `AndroidBridge/app/src/main/java/com/pmca/bridge/core/PmcaController.java`

Обнаруженные методы:
- `submitToTermux(String command)`
- `waitForTermuxResult(String operationId, long timeoutMs)`
- `sendToTermux(String command)`
- `copy(String text, String label)`
- `readClipboard()`
- `runNativeCommand(String command)`

Контроллер создаёт `TermuxBridgeAdapter` и `ClipboardCopyModule`.

Статус: `PRESENT`.

Архитектурное замечание: контроллер используется несколькими компонентами
интерфейса. Пока не подтверждено, что абсолютно все операции проходят
через единую точку управления.

### 4.3. Модуль буфера обмена

**Файл:** `AndroidBridge/app/src/main/java/com/pmca/bridge/clipboard/ClipboardCopyModule.java`

Обнаруженные операции:
- запись текста в системный буфер;
- чтение текста из системного буфера.

Статус: `PRESENT`.

Важное замечание: `FloatingPanelService.java` также содержит прямые
обращения к `ClipboardManager` и `ClipData`.

Следовательно, единственность `ClipboardCopyModule` как исполнителя
операций с буфером обмена пока не обеспечена.

Не удалять прямые обращения до выяснения их назначения и проверки
зависимых сценариев.

### 4.4. Адаптер моста Termux

**Файл:** `AndroidBridge/app/src/main/java/com/pmca/bridge/termux/TermuxBridgeAdapter.java`

Обнаруженные методы:
- `submitShellCommand(String command)`
- `waitForResult(String operationId, long timeoutMs)`
- `sendShellCommand(String command)`
- `runNativeCommand(Context context, String command)`

Назначение: взаимодействие Android-приложения с Termux и передача команд.

Статус: `PRESENT`.

### 4.5. Обработчик результата Termux

**Файл:** `AndroidBridge/app/src/main/java/com/pmca/bridge/termux/TermuxResultService.java`

Обнаруженные операции:
- обработка входящего Intent;
- извлечение данных результата;
- нормализация данных;
- сохранение и широковещательная отправка результата.

Статус: `PRESENT`.

Фактическую обработку разных форматов результата следует оценивать
по отдельным тестам, а не только по наличию методов.

### 4.6. Журнал

**Файл:** `AndroidBridge/app/src/main/java/com/pmca/bridge/logging/PmcaLogger.java`

Обнаруженные методы:
- `log(String message)`
- `getLastLines()`
- `getText()`

Используется ограниченная коллекция строк журнала.

Статус: `PRESENT`.

Отдельно требуется подтвердить, что все нужные компоненты действительно
передают события в этот журнал и что интерфейс показывает ожидаемые строки.

### 4.7. Плавающая панель

**Файл:** `AndroidBridge/app/src/main/java/com/pmca/bridge/overlay/FloatingPanelService.java`

Обнаруженные операции:
- создание панели;
- перемещение панели;
- вставка текста из буфера;
- отправка команд;
- выполнение команды из буфера;
- копирование результата;
- обновление состояния;
- приём результата Termux.

Статус: `PRESENT`.

Примечание: панель создаёт собственный экземпляр контроллера.
Её работа должна проверяться отдельно от главного окна.

### 4.8. Вспомогательная Activity буфера обмена

**Файл:** `AndroidBridge/app/src/main/java/com/pmca/bridge/overlay/ClipboardPasteActivity.java`

Обнаруженные операции:
- получение текста из буфера;
- передача текста на обработку;
- изменение состояния;
- отправка широковещательного сообщения.

Статус: `PRESENT`.

Поведение окна при обработке команды проверяется отдельно.
Успешный возврат результата Termux не доказывает, что главное окно
PMCA автоматически откроется после каждого сценария.

### 4.9. Получатель события установки

**Файл:** `AndroidBridge/app/src/main/java/com/pmca/bridge/InstallStatusReceiver.java`

Назначение: обработка события, связанного с установкой пакета.

Статус: `PRESENT`.

## 5. Известные связи компонентов

По результатам статического аудита:

1. `MainActivity` создаёт `PmcaController`.
2. `FloatingPanelService` создаёт `PmcaController`.
3. `ClipboardPasteActivity` создаёт `PmcaController` для чтения буфера
   и обработки текста.
4. `PmcaController` создаёт `TermuxBridgeAdapter`.
5. `PmcaController` создаёт `ClipboardCopyModule`.
6. `TermuxBridgeAdapter` запускает `TermuxResultService` для обработки
   результата команды.
7. `TermuxResultService` рассылает результат через Broadcast.
8. `MainActivity` и `FloatingPanelService` содержат обработчики результата.
9. `FloatingPanelService` напрямую обращается к Android Clipboard API.

Эти связи подтверждены наличием соответствующих вызовов в исходном коде.
Они не означают, что целевая архитектура со всеми фильтрами, очередью
и маршрутизатором уже реализована.

## 7. Известные результаты испытаний

По состоянию на 10 октября 2026 года в истории проекта зафиксирован
успешный тест команды Termux с кодом завершения `0`.

Тест подтвердил выполнение конкретной команды и возврат текста результата.

В одном из испытаний после обработки команды оставалась видимой плавающая
панель, а главное окно не открывалось автоматически.

Эти результаты относятся только к описанным сценариям и не являются
подтверждением работоспособности всех функций PMCA.

## 8. Приоритеты дальнейшей проверки

1. Проверить путь: главное окно → контроллер → Termux → результат.
2. Проверить такой же путь из плавающей панели.
3. Проверить вставку из буфера и выполнение вставленной команды.
4. Проверить копирование результата и отсутствие потери текста.
5. Определить, какие обращения к буферу должны быть сосредоточены
   в `ClipboardCopyModule`.
6. Установить, какие механизмы защиты от повторной обработки реально
   существуют в исходниках.
7. Сверить фактические результаты с `MODULE_REGISTRY.md`.
8. После проверок обновить `CURRENT_STATE.md` и `PROJECT_STATUS.md`.

## 9. Правила безопасного развития

- Не переписывать работающие компоненты только ради переименования.
- Не создавать второй мост или второй постоянно работающий демон.
- Не удалять существующие обращения до проверки их назначения.
- Перед изменением существующего кода сохранять резервную копию.
- Не считать наличие класса доказательством его полной интеграции.
- Не считать успешный тест одного сценария доказательством всей системы.
- Сначала фиксировать фактическую реализацию, затем менять архитектуру.
- Не объявлять модуль `VERIFIED` без конкретного успешного теста.
