# PMCA — реестр модулей

Назначение: учёт существующих компонентов, зависимостей и готовности к переносу.

## Правила

- Один модуль отвечает за одну определённую функцию.
- Центральный контроллер координирует операции.
- Зависимости между модулями должны быть явными.
- Нельзя считать модуль переносимым только потому, что он находится в отдельном файле.
- Перед изменением реализации создаётся резервная копия и выполняется проверка сборки.

## Статусы

- `FILE`: отдельный исходный файл.
- `AUDIT_REQUIRED`: зависимости требуют проверки.
- `PORTABILITY_UNVERIFIED`: независимость и переносимость не подтверждены.

## Компоненты

| Компонент | Предполагаемая роль | Статус |
|---|---|---|
| MainActivity | Главное окно и пользовательский ввод | AUDIT_REQUIRED |
| PmcaController | Координация операций | AUDIT_REQUIRED |
| ClipboardCopyModule | Копирование в буфер обмена | AUDIT_REQUIRED |
| ClipboardPasteActivity | Вставка текста | AUDIT_REQUIRED |
| FloatingPanelService | Плавающая панель | AUDIT_REQUIRED |
| TermuxBridgeAdapter | Передача команд в Termux | AUDIT_REQUIRED |
| TermuxResultService | Получение результатов Termux | AUDIT_REQUIRED |
| DuplicateGuard | Защита от повторных активных команд | AUDIT_REQUIRED |
| PmcaLogger | Журналирование | AUDIT_REQUIRED |
| InstallStatusReceiver | Получение статуса установки | AUDIT_REQUIRED |

## Важное замечание

Этот список является исходным ориентиром, а не утверждением, что все перечисленные
файлы присутствуют в текущем исходном дереве. Фактический состав и зависимости
фиксируются в отчёте аудита.

Автоматическое изменение Java-кода не выполняется этим этапом.
