# ПАСПОРТ ПРОЕКТА PMCA

Версия паспорта: 1.0
Дата фиксации: 2026-10-09

## 1. Название

Portable Modular Controller Architecture (PMCA).

## 2. Назначение

Создать переносимую модульную систему, в которой центральный контроллер
управляет обработкой входных данных, маршрутизацией, выполнением операций,
журналированием и передачей результата пользователю.

Одна функция — один актуальный модуль.
Один центральный контроллер — единая точка управления последовательностью.

## 3. Целевые возможности

- Приём ручного ввода.
- Приём данных из чата.
- Передача данных в Termux.
- Вызов специализированных модулей.
- Защита от повторной обработки и циклов.
- Очередь операций и контроль состояния.
- Журналирование событий и ошибок.
- Автоматическое копирование результата в буфер обмена.
- Просмотр последних 50 строк журнала в приложении.
- Кнопка «Скопировать лог».
- Разделение ручного ввода, передачи в чат и передачи в Termux.
- Переносимость и возможность расширения без переписывания ядра.

## 4. Планируемый поток обработки

INPUT
  -> Controller
  -> Parser
  -> Duplicate Guard
  -> Processing Gate
  -> Queue
  -> Router
  -> Module / Adapter
  -> Logger
  -> OUTPUT

Передача результата в буфер обмена должна быть частью управляемого
потока, а не набором независимых реализаций, разбросанных по проекту.

## 7. Зафиксированное поведение буфера обмена

Механизм автокопирования существует в Termux-мосте.

Для обычных команд предусмотрены этапы:
- копирование входных данных;
- обработка команды;
- запись результата;
- копирование ответа.

Для CLIPBOARD_GET копирование входных данных пропускается,
чтобы не уничтожить буфер до чтения его содержимого.

Для операций копирования применяется ограниченный по времени вызов:
timeout 3s termux-clipboard-set

Недоступность буфера не должна приводить к бесконечному ожиданию.

## 8. Последние зафиксированные результаты

На 2026-10-09 были зафиксированы:
- успешная обработка TEST;
- успешная обработка SHELL;
- успешное чтение буфера через CLIPBOARD_GET;
- успешное копирование ответа;
- успешная передача ответа размером около 16 КБ;
- отсутствие обнаруженного обрезания в этой проверке;
- один экземпляр демона после контролируемого перезапуска.

Это исторические результаты, а не гарантия текущего состояния устройства.

Повторять эти проверки без конкретной причины не нужно.

## 9. Ограничения достоверности

Этот паспорт составлен по ранее зафиксированным результатам работы.

Текущая версия всех файлов и процессов устройства здесь не проверялась.
При реальном противоречии между паспортом и рабочим состоянием
приоритет имеет фактическое состояние, которое следует исправить
в документации после подтверждения.

Не следует заново исследовать весь проект только ради подтверждения
каждой исторической записи.

## 10. Цель ближайшего этапа

Довести единый актуальный механизм автокопирования до выделенного
модуля, подключённого через центральный контроллер.

После подключения соответствующая старая реализация отключается.
Необходимо обновить реестр, журнал изменений и паспорт.
