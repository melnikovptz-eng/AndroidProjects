# PMCA — PROJECT STATUS

## Project
Portable Modular Controller Architecture

## Short Name
PMCA

## Version
0.1.0

## Status
DOCUMENTATION_ALIGNMENT

## Project Purpose
PMCA is intended to provide a portable, modular architecture with a
centralized controller, clearly defined module boundaries, controlled
message routing, duplicate protection, logging, and verifiable execution
flows.

The architecture description defines project goals. It does not mean that
every listed component has already been implemented or integrated.

## Target Architecture
- Controller
- Module System
- Module Contract
- Module Manifest
- Queue
- Router
- Duplicate Guard
- Processing Gate
- Logger
- State Machine
- Adapters
- Health Check
- Watchdog
- Error Isolation
- Versioning
- Portability Check
- Module Export
- Developer Mode

## Rules
- Сначала контракт — потом реализация.
- Модули независимы.
- Ошибка одного модуля не должна ломать систему.
- Controller — единственный центр управления.
- UI не управляет внутренней логикой модулей напрямую.
- STUB не считается PASS.
- Рабочие legacy-компоненты не переписываются без необходимости.

Эти правила являются требованиями архитектуры. Их полное соблюдение
должно подтверждаться проверкой реализации, а не только документацией.

## Confirmed Verification
Подтверждён один конкретный сценарий передачи тестовой команды в
Termux и возврата результата:

- тестовая команда выполнена;
- результат получен;
- STDERR пустой;
- код завершения: 0.

Проверка подтверждает только этот сценарий. Она не доказывает
работоспособность всех путей передачи команд, интерфейсов и модулей.

## Known Limitations
- Не подтверждено, что все операции проходят через один экземпляр
  PmcaController.
- Не подтверждено, что ClipboardCopyModule является единственным
  компонентом, работающим с буфером обмена.
- Parser не подтверждён как отдельный интегрированный компонент.
- Duplicate Guard не подтверждён как отдельный интегрированный компонент.
- Processing Gate не подтверждён как отдельный интегрированный компонент.
- Queue не подтверждена как отдельный интегрированный компонент.
- Router не подтверждён как отдельный интегрированный компонент.
- Основной экран, плавающая панель, вставка из буфера и возврат результата
  требуют отдельных проверок пользовательских сценариев.
- Статический анализ исходников сам по себе не подтверждает поведение
  приложения во время выполнения.

## Documentation Alignment Exit Criteria
Этап согласования документации считается завершённым, когда:

- документы отражают проверенное состояние проекта;
- целевые компоненты не обозначены реализованными без доказательств;
- подтверждённые сценарии перечислены с указанием их границ;
- перед изменением существующих документов создаются резервные копии;
- изменения документов проверяются до замены исходных файлов;
- исходники, APK и мост Termux не изменяются в ходе одной только
  работы над документацией.

## Safe Change Policy
- Не удалять рабочие файлы без обоснованной необходимости.
- Не переписывать рабочие legacy-компоненты без необходимости.
- Не изменять код и APK при обновлении документации.
- Не запускать дополнительные фоновые процессы без необходимости.
- Перед изменениями проверять исходное состояние и сохранять резервную копию.
- Отделять статическое обнаружение компонента от проверки его работы.
- Отделять успешный единичный тест от подтверждения всей системы.

## Document Maintenance
При существенном изменении реализации обновлять PROJECT_STATUS.md,
CURRENT_STATE.md, MODULE_REGISTRY.md и IMPLEMENTATION_MAP.md так,
чтобы между ними не возникало противоречий.

Каждое утверждение о работоспособности должно иметь понятное основание:
результат теста, проверку интеграции или явно обозначенное ограничение.
