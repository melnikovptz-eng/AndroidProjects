# Паспорт проекта: VoiceActivation Calibration

- **Проект:** VoiceActivation Calibration
- **Назначение:** отдельное Android-приложение для измерительной калибровки акустического триггера и распознавания русских голосовых команд.
- **Устройство проверки:** TECNO KJ6, Android 13, ARM64.
- **Язык реализации:** Kotlin.
- **Новая реализация:** да. Старые исходники, алгоритмы, интерфейс и настройки VoiceActivation не использовать как основу. Разработка ведётся в отдельном каталоге `VoiceActivation/CalibrationApp`.
- **Пакет:** `ru.voiceactivation.calibration`.
- **Основной принцип:** параметры не объявляются оптимальными заранее. Оптимум определяется сериями измерений на устройстве и записях пользователя.

## 1. Функциональные задачи

### 1.1. Захват и измерение звука
- [ ] Захват моно PCM с микрофона через AudioRecord.
- [ ] Настраиваемая частота дискретизации; основной профиль 16 кГц, дополнительная проверка поддерживаемых частот устройства.
- [ ] Отображение текущего RMS, peak и уровня в dBFS.
- [ ] Отображение фонового шума, оценённого в dBFS.
- [ ] Расчёт отношения сигнал/шум (SNR) в dB.
- [ ] График уровня сигнала, фонового шума и порога в реальном времени.
- [ ] Обработка ошибок разрешения, недоступности микрофона и AudioRecord; корректное освобождение ресурса.
- [ ] Видимое состояние микрофона: STOPPED / LISTENING / ERROR. Запись начинается только по явному нажатию пользователя.

### 1.2. Настройка акустического триггера
Пользователь должен вручную менять и видеть числовое значение каждого параметра:
- [ ] Порог срабатывания относительно фонового шума, dB.
- [ ] Абсолютный минимальный порог уровня, dBFS.
- [ ] Гистерезис включения/выключения, dB.
- [ ] Минимальное время превышения порога, ms.
- [ ] Минимальная длительность речи, ms.
- [ ] Время тишины для завершения фразы, ms.
- [ ] Максимальная длительность одного речевого сегмента, ms.
- [ ] Время предзаписи (pre-roll), ms.
- [ ] Окно оценки фонового шума, ms.
- [ ] Скорость адаптации фонового шума.
- [ ] Пауза блокировки повторного триггера (cooldown), ms.
- [ ] Выбор RMS/peak для основного критерия; отображение обоих измерений.
- [ ] Сброс параметров к исходному нейтральному профилю.
- [ ] Изменение любого параметра без перезапуска приложения.

### 1.3. Калибровка фонового шума
- [ ] Отдельный этап измерения тишины с таймером и накоплением статистики.
- [ ] Измерение в нескольких условиях: тихая комната, бытовой фон, повышенный фон.
- [ ] Сохранение среднего, медианы, p90 и разброса уровня шума.
- [ ] Не обновлять оценку шума по кадрам, уже классифицированным как речь.
- [ ] Отображать текущую оценку и стабильность фона.
- [ ] Возможность ручного запуска и остановки измерения.

### 1.4. Проверка триггера и сегментации речи
- [ ] Режим теста без распознавания: показать, когда триггер открыл и закрыл речевой сегмент.
- [ ] Визуальная маркировка срабатываний на графике.
- [ ] Запись тестовых меток: речь / шум / тишина / ложное срабатывание / пропуск.
- [ ] Счётчики срабатываний, пропусков и ложных запусков.
- [ ] Измерение времени реакции и длительности сегмента.
- [ ] Ручная оценка результата каждого испытания пользователем.
- [ ] Повторяемые серии испытаний с неизменяемым снимком параметров серии.

### 1.5. Распознавание речи Vosk
- [ ] Подключение локального Vosk Android runtime и русской модели, без облачной отправки аудио.
- [ ] Проверка наличия модели и понятный статус загрузки/готовности.
- [ ] Передача в Vosk только выделенного речевого сегмента.
- [ ] Отображение partial и final результатов отдельно.
- [ ] Отображение полного распознанного текста в окне испытаний.
- [ ] Измерение задержки распознавания.
- [ ] Обработка отсутствующей/повреждённой модели и ошибок распознавателя.
- [ ] Возможность испытать ASR на записанном аудиофрагменте, если формат/источник поддержан.

### 1.6. Сопоставление обращения «Яша»
- [ ] Нормализация регистра, пробелов и пунктуации.
- [ ] Точное совпадение «Яша».
- [ ] Настраиваемое нечёткое текстовое сходство.
- [ ] Настраиваемый список допустимых вариантов: «Яжа», «Яаша», «Ясша» и дополнительные варианты.
- [ ] Отображение найденного токена, степени сходства и причины принятия/отклонения.
- [ ] Испытания на похожих посторонних словах для измерения ложных совпадений.
- [ ] Не считать фонетическую близость гарантией правильного распознавания: решение проверяется на реальных результатах Vosk.

### 1.7. Двойные и одиночные команды
- [ ] Режим «только обращение» для отдельного тестирования «Яша».
- [ ] Режим двойной команды: обязательное обнаружение обращения и второго слова/фразы.
- [ ] Настраиваемый тайм-аут ожидания второго слова.
- [ ] Настраиваемая максимальная пауза между обращением и действием.
- [ ] Настраиваемый список действий, первоначально включая «поехали».
- [ ] Проверка порядка слов и возможность задать допустимый порядок.
- [ ] Отдельные статусы: обращение найдено / действие найдено / команда полная / команда неполная.
- [ ] Вывод результата в формате «КОМАНДА: … — ОК» только после выполнения заданных критериев.
- [ ] Испытания неполных, переставленных и посторонних фраз.

### 1.8. Эксперименты и автоматический подбор
- [ ] Сохранение каждого прогона с датой, параметрами, метками и результатами.
- [ ] Сравнение нескольких профилей параметров на одинаковом наборе испытаний.
- [ ] Расчёт true positive, false positive, false negative, precision, recall и F1 при наличии корректных меток.
- [ ] Отдельный расчёт ложных запусков на минуту фонового аудио.
- [ ] Измерение задержки: медиана и p95.
- [ ] Подбор кандидатов параметров по заданной целевой функции; целевая функция и веса должны быть видимы и редактируемы.
- [ ] Не подменять реальные измерения синтетическими числами.
- [ ] Выдавать рекомендацию только при достаточном количестве размеченных испытаний; показывать объём выборки и ограничения.
- [ ] Повторное контрольное испытание рекомендованного профиля.
- [ ] Ручное подтверждение применения рекомендованного профиля.

### 1.9. Профили, данные и экспорт
- [ ] Сохранение нескольких именованных профилей в локальном хранилище.
- [ ] Экспорт/импорт профилей и статистики в JSON.
- [ ] Сохранение истории испытаний после перезапуска.
- [ ] Возможность удалить отдельную серию и очистить историю с подтверждением.
- [ ] Стабильная схема JSON с версией.
- [ ] Не сохранять необработанный звук по умолчанию; запись тестовых аудио включается отдельно и явно.

### 1.10. Интерфейс
- [ ] Главный экран с состоянием микрофона, живыми уровнями и графиком.
- [ ] Отдельные разделы: «Звук», «Триггер», «Vosk», «Команды», «Испытания», «Профили».
- [ ] Все критические параметры имеют подпись, единицу измерения, текущее значение и краткую подсказку.
- [ ] Числовой ввод/ползунок с точной настройкой.
- [ ] Кнопки «Начать измерение», «Остановить», «Тест триггера», «Сохранить профиль», «Экспорт».
- [ ] Окно распознанной команды с явным результатом «ОК / НЕ ОК».
- [ ] UI не блокирует поток захвата звука и не вызывает ANR.
- [ ] Корректная работа при повороте экрана и восстановление выбранного профиля.

## 2. Технические и качественные требования
- [ ] Новая самостоятельная структура исходников, не копировать прежнюю реализацию.
- [ ] Разделение AudioCapture, LevelMeter, NoiseEstimator, SpeechSegmenter, VoskEngine, CommandMatcher, ExperimentRunner, ProfileRepository и UI.
- [ ] Потокобезопасная передача аудиокадров.
- [ ] Ограниченные очереди и отсутствие неограниченного накопления PCM в памяти.
- [ ] Отсутствие постоянных циклов опроса, когда микрофон остановлен.
- [ ] Корректное освобождение AudioRecord/recognizer при остановке и уничтожении экрана.
- [ ] Локальная обработка аудио.
- [ ] Логи содержат состояние и ошибки, но не сырое аудио и не лишние персональные данные.
- [ ] Unit-тесты математики RMS/dBFS/SNR, оценки шума, гистерезиса, сегментации, нормализации и fuzzy matching.
- [ ] Тесты импорта/экспорта и расчёта метрик на заранее размеченных наборах.
- [ ] Статическая проверка разрешений, manifest, зависимостей и лицензий.
